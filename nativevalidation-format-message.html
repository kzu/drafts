FormatMessage in NativeValidation

dotnet/runtime#132853 lets a caller hand a validation attribute a message template. The attribute still fills its own placeholders. NativeValidation now does that same job without constructing the attribute.

The runtime method

dotnet/runtime#132853 backports #132764 to release/11.0. The approved API, from #132605, is a public virtual method on ValidationAttribute:

public virtual string FormatMessage(string format, string name)
{
    return string.Format(CultureInfo.CurrentCulture, format, name);
}

The base method substitutes only the display name. Built-in attributes that need more values override it. FormatErrorMessage now calls FormatMessage with the attribute’s own template, so the placeholder list lives in one place.

That split is what localization hosts needed. Microsoft.Extensions.Validation and Blazor look up a translated sentence, then call attribute.FormatMessage(localizedTemplate, displayName). The host owns the words. The attribute owns {1} and {2}.

The motivating mismatch is FileExtensionsAttribute. The attribute formats a normalized, dot-prefixed list. Hosts that copied the raw Extensions property formatted PDF, .TXT while the attribute formatted .pdf, .txt.

Why NativeValidation does not call it

NativeValidation targets net10.0. FormatMessage is a .NET 11 method, so the library cannot cref it or dispatch it. More importantly, the generator never constructs a ValidationAttribute. It inlines the attribute’s arguments into a direct call on NativeValidator, which is what keeps object validation free of reflection.

Calling the virtual method would require an attribute instance. Several of those constructors are themselves trim-unsafe (MinLength, MaxLength, Length, Compare, Range(Type, string, string)). The support that fits this library is to reproduce the placeholder contract inside NativeValidator, where the arguments are already known.

The options source generator took the other route. It emits replica attribute types and, when the compilation can see the new API, overrides FormatMessage on those replicas. NativeValidation has no replica types, so there is nothing to override.

The placeholder contract

{0} is always the display name, or the member name when no display name was copied from [Display] or [DisplayName]. The rest follow the override on each built-in attribute. StringLength and Length use opposite orders. That is the whole reason the arguments live on the attribute instead of in the host.

Public helpers expose that contract when the caller already has a template and the arguments: FormatMessage, FormatStringLengthMessage, FormatMinLengthMessage, FormatMaxLengthMessage, FormatLengthMessage, FormatRangeMessage, FormatPatternMessage, FormatCompareMessage, and FormatFileExtensionsMessage. A null format throws ArgumentNullException. Formatting uses CultureInfo.CurrentCulture, as the runtime method does.

The lab below uses the same argument order. It substitutes {0}, {1}, and {2}. The library’s real path is string.Format, so alignment and format specifiers behave as they do on the attribute.

    File extensions

    FormatFileExtensionsMessage normalizes before formatting. Spaces and dots are removed, the text is lowercased, each item is prefixed with a dot, and the items are joined with a comma and a space. A blank value uses png,jpg,jpeg,gif. The check that validates a filename uses that same list.

    Raw property

    PDF, .TXT

    What {1} receives

    .pdf, .txt

    static string[] ParseExtensions(string? extensions)
{
    var source = string.IsNullOrWhiteSpace(extensions) ? "png,jpg,jpeg,gif" : extensions!;
    var normalized = source.Replace(" ", "").Replace(".", "").ToLowerInvariant();
    var parts = normalized.Split(',');
    for (var i = 0; i < parts.Length; i++)
        parts[i] = "." + parts[i];
    return parts;
}

    Choosing the template

    Each check already accepted an errorMessage string. The generator copies ErrorMessage as a literal, or emits a read of the public static resource property named by ErrorMessageResourceName. When neither is set, the generator passes null and the check used a fixed English sentence.

    That English sentence is the gap FormatMessage closes for hosts. The attribute did not carry a template, and the host still needs to supply one at format time, with the attribute’s arguments. NativeValidator.MessageTemplate is that hook. It is consulted only when the attribute did not set a message.

    static ValidationResult Result(string attribute, string? errorMessage, string fallback,
    string memberName, string? displayName, params object?[] args)
{
    var template = errorMessage ?? MessageTemplate?.Invoke(attribute, fallback) ?? fallback;
    return new ValidationResult(
        FormatMessage(template, displayName ?? memberName, args),
        new[] { memberName });
}

    The delegate is process-wide. Set it before validation runs on other threads. A resource manager inside the delegate can still follow CurrentUICulture, which is the usual localization pattern: one delegate, many cultures.

    NativeValidator.MessageTemplate = (attribute, fallback) => attribute switch
{
    nameof(StringLengthAttribute) => "len {0} max {1} min {2}",
    nameof(MaxLengthAttribute) => "max {0} {1}",
    nameof(FileExtensionsAttribute) => "El campo {0} solo acepta: {1}",
    _ => null
};

    Generated checks

    The generator did not change. It already passes the template slot into NativeValidator. A member written like this:

    public void Rename([Required, StringLength(8, MinimumLength = 2)] string? name, [Range(1, 10)] int attempt)

    is emitted as a direct call with a null template:

    NativeValidator.StringLength(value, 2, 8, "name", null, null);

    With the delegate above, a value of "a" fails as len name max 8 min 2. The maximum is {1} because this call is StringLength. An explicit ErrorMessage = "Need {0}" on an attribute is still passed through as the first template and is left as written. MessageTemplate does not replace it.

    Range(typeof(T), minimum, maximum) parses the bounds before formatting. That matches RangeAttribute.FormatMessage, which calls SetupConversion and then formats the Minimum and Maximum properties.

    What stays out

    A custom ValidationAttribute subclass can override FormatMessage on .NET 11. NativeValidation still reports that subclass as NVA001 and does not run it. Virtual dispatch would need an instance, and the generator’s rule is that it does not construct an arbitrary attribute to call into it.

    Cast failures and count failures are not FormatMessage results. They stay as their own sentences. A CustomValidation method that returns its own ValidationResult.ErrorMessage keeps that message. If the message contains {0}, it is formatted with the display name only, which is the base FormatMessage contract. The delegate applies when that method returns an empty message and the attribute itself did not set one. The fallback in that case is {0} is not valid.

    How it was checked

    On the library’s net10.0 tests, each helper and each failing check was compared with FormatErrorMessage on the real attribute, using a template that exposes every placeholder. The runtime change keeps that argument order and routes FormatErrorMessage through FormatMessage, so the net10 oracle is the same contract.

    On the installed .NET 11 RC 2 (11.0.100-rc.2.26504.105), a small program called FormatMessage on the real attributes and compared it with the new helpers. These pairs matched:

    • StringLengthAttribute(4) with minimum 2, template {0}/{1}/{2}
    • MinLengthAttribute(2) and MaxLengthAttribute(2), template {0}/{1}
    • LengthAttribute(2, 4), template {0}/{1}/{2}
    • RangeAttribute(1, 10), template {0}/{1}/{2}
    • RegularExpressionAttribute("^a+$"), template {0}/{1}
    • CompareAttribute("Password"), template {0}/{1}
    • FileExtensionsAttribute for PDF, .TXT and for the default list
    • RequiredAttribute, template Need {0}

    The test project then passed 30 tests, including one that sets MessageTemplate and validates a generated StringLength parameter and a generated MaxLength property. A Release build of the library reported 0 warnings.
